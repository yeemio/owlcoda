OwlCoda runtime architecture

本地优先的 AI 编程运行时

npm 0.14.53 updated 2026-06-02 Developer Preview

OwlCoda 现在不是一个“聊天壳”，而是一套在用户机器上运行的 workbench runtime： native REPL、browser Admin、headless run、shared daemon、工具执行、权限/溯源/任务守卫、 provider middleware 和本地证据账本围成同一个闭环。模型和数据都归用户，公开入口是 npm 包。

闭环 1: 输入到行动

用户输入进入 REPL/headless，经过 mode、intent、task、write/provenance 约束，再落到工具或模型请求。

闭环 2: 模型到证据

模型输出不只看自报；工具调用、路径、mtime、artifact、telemetry 都进入可审计 runtime fact。

闭环 3: 包到官网

npm 包是用户安装真相；public router 和网站只承载公开文案、安装说明和 changelog。

现在哪些是默认、哪些还在观察

避免把 shadow / opt-in 写成 default-on

Default-on

  • Native REPL 是默认交互路径，Admin 负责 first-run 配置。
  • Permission Modes 默认可用，默认 mode 仍是 normal。
  • Project Map runtime control plane 默认开启，失败降级不炸 loop。
  • Daemon version drift / orphan daemon recovery 已进入启动保护。

Opt-in / dogfood

  • Adaptive concurrency 仍按 flag / coordinator dogfood 节奏推进。
  • Provenance / GATE_V2 类阻断线继续按 evidence gate 规则推进。
  • Auto mode 是可选工作方式，不等于全自动无守卫。

Shadow / debug-only

  • Evidence-ledger fidelity 目前是观测与人工 review，不是拒绝 gate。
  • SWE-bench 数据不在官网宣称为产品分数。
  • Architecture board 不替代 package smoke、doctor 和 clean-clone release truth。

相比旧图变化最大的地方

0.14.46 到 0.14.53 的结构性变化

控制面变厚了

Permission Modes从 flag 试用变成默认可见的 mode 系统，plan/normal/auto 成为 hard boundary。
Project Map从项目扫描工具升级为 runtime control plane 的 context source。
Daemon identity旧 daemon、orphan port holder、live client 都进入 runtime 判断，不再靠用户猜。
Slash surface/copy、/editor、/tasks、/hooks 补齐展示和 handler 漂移保护。

事实账本更硬了

No-progress能区分 read-heavy investigation、plan mode、interpreter-inline artifact progress。
Bash risk/dev/null 和标准流重定向不再误判为 mutating artifact write。
Fidelity shadow模型硬锚点、路径事实和 compaction summary 有了 runtime fact 对账面。
Cost/cacheprefix-cache tokens 进入 per-model 与 session total，缓存效果不再只靠感觉。

边界口径：OwlCoda 不捆绑模型、不托管会话、不提供云端控制面。用户配置自己的 local runtime 或 cloud API key。 官网架构图只讲公开运行结构；内部 release provenance、私有文档、operator handoff 和未公开评分不放进公共页面。
